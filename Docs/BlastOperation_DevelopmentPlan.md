## 0. 文档目标

这份文档用于把《爆破行动》从“UE5 射击模板 + 素材包”推进到“可长期迭代的 5v5 竞技爆破 FPS”。它不是一次性概念稿，而是项目总纲：后续每个系统、每张地图、每把武器、每个 UI、每个版本计划，都应该能回到这里找到方向。

文档的核心原则：

1. 先做一个可信、可测试、可联网的竞技垂直切片。
2. 枪法、信息、道具、经济、地图控制五件事必须互相制约。
3. 早期不要追求“像某个成熟游戏一样大”，要追求“每一秒都像竞技游戏”。
4. 所有核心玩法从第一天起按多人联机、服务器权威、反作弊、回放和数据分析来设计。
5. 参考 CS 和无畏契约的品类经验，但不能复制地图、角色、武器命名、美术符号、音效识别或商业表达。

## 2. 产品定位

### 2.1 一句话定位

《爆破行动》是一款以枪法为核心、以团队道具和信息博弈为战术深度的 5v5 回合制竞技爆破 FPS。

### 2.2 核心竞品参照

参照对象：

- CS 系列：高价值枪法、经济系统、投掷物、地图控制、低随机性。
- 无畏契约：角色定位、技能信息战、清点/控点工具、观赏性和战术分工。

本项目不应选择“完全像 CS”或“完全像无畏契约”。更合适的方向是：

**枪法权重接近 CS，战术工具表达接近近未来装备，不做强魔法英雄技能，不做大招翻盘游戏。**

### 2.3 差异化方向

建议将《爆破行动》的差异化定为：

1. **强枪法优先**
   - 击杀主要来自准星、站位、时机和压枪。
   - 道具创造机会，但不替代击杀。

2. **角色轻量化**
   - 不做复杂英雄大招体系。
   - 玩家选择“战术职能/装备包”，而不是选择强叙事英雄。
   - 同一职能可以有多个装备组合，减少角色锁定造成的平衡压力。

3. **信息战可读**
   - 侦察、遮蔽、干扰、诱骗都必须有清晰声音、视觉、反制窗口。
   - 避免不可读、不可反制、隔墙无成本获取全部信息。

4. **爆破器交互更丰富**
   - 安装、保护、拆除是模式中心。
   - 爆破器可以成为 UI、音效、地图目标和经济奖励的强识别资产。

5. **地图强调“推进-控图-转点-残局”**
   - 每张地图至少包含两条主要进攻路线、一个中路控制区、两个爆破点。
   - 让进攻方有假打、转点、夹击空间。
   - 让防守方有前压、回防、交叉火力和反清道具空间。

### 2.4 不做什么

早期明确不做：

- 不做大逃杀。
- 不做开放世界。
- 不做 32v32 大战场。
- 不做付费属性成长。
- 不做能直接秒杀全队的终极技能。
- 不做复杂垂直移动英雄。
- 不做移动端优先设计。
- 不做随机弹道主导胜负的娱乐 FPS。

## 3. 目标平台与体验指标

### 3.1 首发平台

第一阶段建议只面向 PC：

- Windows 为主。
- 后续评估 Steam Deck/Linux。
- Mac 只作为开发便利，不作为竞技首发承诺。

### 3.2 操作输入

首发只保证：

- 键盘鼠标。
- 可选手柄基础支持，但不作为竞技平衡目标。

### 3.3 性能目标

本项目是竞技 FPS，性能优先级高于纯画质。

最低体验目标：

- 1080p 低画质稳定 60 FPS。
- 中端 PC 1080p 稳定 144 FPS。
- 推荐配置 1440p 稳定 144 FPS。
- 服务器单局 10 名玩家 + 观战 + 掉线重连，稳定运行。
- 客户端输入到开火反馈要有即时本地响应。

### 3.4 网络目标

竞技目标：

- 专用服务器权威。
- 客户端不决定命中结果。
- 支持延迟补偿。
- 支持掉线重连。
- 支持服务器回放/裁判数据。
- 支持基础反作弊和异常行为检测。

MVP 阶段可以先局域网/Listen Server 验证，但任何核心代码都应按专用服务器迁移来设计。

## 4. 核心设计支柱

### 4.1 支柱一：可信枪感

一款爆破 FPS 的底层信任来自“我为什么打中/没打中”。因此：

- 每把武器必须有稳定弹道规则。
- 开火音、后坐力、镜头反馈、命中反馈必须一致。
- 第一人称动画不能遮挡关键视野。
- 枪械数值必须能数据驱动调参。
- 服务端命中裁定必须可回放、可调试。

### 4.2 支柱二：可读战术

战术道具不能只追求酷。每个道具都要回答：

- 谁释放了它？
- 它影响哪里？
- 持续多久？
- 是否可以躲避？
- 是否可以摧毁？
- 是否可以反制？
- 敌我双方如何听见/看见它？

### 4.3 支柱三：回合压力

每回合都要有阶段变化：

1. 买装和部署。
2. 首波控图。
3. 侦察与消耗。
4. 进点或假打。
5. 安包后防守。
6. 残局和拆包。

如果一张地图或一个系统无法制造这些阶段，它就不是合格的爆破竞技内容。

### 4.4 支柱四：公平竞技

公平不只是反作弊，还包括：

- 不卖属性。
- 清晰命中反馈。
- 清晰声音定位。
- 清晰视觉层级。
- 排位匹配尽量避免实力悬殊。
- 地图双方胜率长期接近。
- 版本更新可解释、可追踪。

### 4.5 支柱五：长期可维护

项目必须从一开始建立：

- 版本控制。
- 命名规范。
- 数据表。
- 自动化测试。
- 性能预算。
- 打包流程。
- 崩溃收集。
- 日志和遥测。

否则一旦内容增多，竞技调参会变成不可控混乱。

## 5. 核心玩法

### 5.1 标准模式

模式名：标准爆破  
人数：5v5  
阵营：进攻方 / 防守方  
目标：进攻方安装并保护爆破器，或消灭防守方；防守方阻止安装、拆除爆破器，或消灭进攻方。  
胜利：率先赢得 13 回合。  
半场：12 回合后攻守互换。  
加时：12:12 后进入加时，每轮加时双方各打 1 回合，领先 2 回合获胜。

### 5.2 单回合流程

建议初版流程：

1. 载入阶段
   - 玩家进入服务器。
   - 同步队伍、角色/装备包、玩家状态。

2. 买装阶段
   - 标准时长：30 秒。
   - 回合开始前双方被限制在出生区。
   - 可购买武器、护甲、道具。
   - 可请求队友购买武器。

3. 行动阶段
   - 标准时长：100 秒。
   - 出生区屏障解除。
   - 进攻方寻找机会安装爆破器。
   - 防守方守点、前压或回防。

4. 安装阶段
   - 爆破器只能在指定爆破区安装。
   - 安装耗时：4 秒。
   - 安装期间玩家不能开火，移动会打断。
   - 安装完成后进入爆破倒计时。

5. 爆破倒计时
   - 爆破器倒计时：40 秒。
   - 防守方拆除耗时：7 秒。
   - 初版不加入拆包钳，减少经济变量。

6. 结算阶段
   - 展示回合胜方、击杀信息、经济变化。
   - 回收/保留装备规则生效。
   - 进入下一回合买装。

### 5.3 胜利条件优先级

回合胜利判断：

- 爆破器爆炸：进攻方胜。
- 爆破器被拆除：防守方胜。
- 爆破器未安装且时间耗尽：防守方胜。
- 爆破器未安装且一方全灭：存活方胜。
- 爆破器已安装且进攻方全灭：回合继续，防守方仍需拆除。
- 爆破器已安装且防守方全灭：进攻方胜。

### 5.4 经济系统

货币名建议：战备点。

初始版本建议数值：

- 初始战备点：800。
- 胜利奖励：3200。
- 连败 1 次奖励：1900。
- 连败 2 次奖励：2400。
- 连败 3 次及以上奖励：2900。
- 安装爆破器团队奖励：每人 300。
- 回合存活保枪：保留武器、护甲剩余值不返还。
- 最大战备点：10000。

击杀奖励建议：

- 手枪：300。
- 冲锋枪：500。
- 步枪：300。
- 霰弹枪：600。
- 狙击枪：100。
- 近战：1500。
- 爆炸物/道具击杀：200。

经济设计目标：

- 输掉手枪局后仍有强制起枪和经济局选择。
- 保枪有价值，但不能鼓励全队长期消极保枪。
- 武器风险和收益要明确。
- 道具成本要影响战术选择。

### 5.5 装备栏

初版装备栏：

- 主武器 1 把。
- 副武器 1 把。
- 近战武器 1 把。
- 护甲 1 件。
- 通用道具 2 到 3 个。
- 职能装备 1 到 2 个。
- 爆破器由进攻方一名玩家携带。

### 5.6 角色/职能方向

建议不做强英雄，而做“战术职能 + 装备包”。

初版五类职能：

1. 突入
   - 负责开路、吃第一波交火、制造突破窗口。
   - 道具：闪光、震撼、近点清理装置。

2. 控场
   - 负责封视野、阻断回防、压缩防守空间。
   - 道具：烟幕、区域干扰、短时阻隔。

3. 侦察
   - 负责发现站位、判断转点、排查近点。
   - 道具：侦察脉冲、微型探测器、声源诱饵。

4. 支援
   - 负责补给、救援信息、辅助进点。
   - 道具：弹药包、临时护盾、烟幕补位。

5. 锚点
   - 负责守点、延缓推进、残局拖时间。
   - 道具：感应器、绊线、低伤害阻滞区。

设计边界：

- 不做治疗复活作为核心能力，避免破坏回合击杀价值。
- 不做隔墙持续透视。
- 不做不可摧毁自动杀敌装置。
- 不做超长位移、飞天、瞬移作为常规能力。
- 每个职能装备必须有声音和视觉提示。

## 6. 武器系统

### 6.1 武器分类

初版武器库建议 14 把左右，不要一开始做太多。

副武器：

- B9 标准手枪：免费/低价，均衡。
- R6 重型手枪：高伤害、低射速。
- S18 自动手枪：近距离压制，弹药消耗快。

冲锋枪：

- Vektor-9：高射速、低穿透、跑打惩罚低。
- MPX-45：中近距离稳定，经济局主力。

步枪：

- AR-21：主力全自动步枪，均衡。
- KX-74：高伤害高后坐，高手向。
- BR-16：三连发/半自动，精准但容错低。

狙击/精确武器：

- DMR-11：半自动精确步枪。
- L96：高价重狙，身体高伤害，开镜惩罚明显。

霰弹枪：

- SG-12：低价近点。
- Auto-8：高价连喷，弹药和距离限制严格。

重武器：

- MG-60：高弹容量，低机动，高压制。

近战：

- 战术刀：移速最高，可高奖励击杀。

### 6.2 武器参数

每把武器至少数据化以下字段：

- 价格。
- 弹匣容量。
- 备弹数量。
- 射速。
- 换弹时间。
- 掏枪时间。
- 收枪时间。
- 首发精准度。
- 连发扩散曲线。
- 垂直后坐力。
- 水平后坐力。
- 后坐恢复时间。
- 站立精准度。
- 蹲下精准度。
- 移动精准度。
- 跳跃精准度。
- 伤害衰减距离。
- 头部倍率。
- 胸部倍率。
- 腹部倍率。
- 腿部倍率。
- 护甲穿透。
- 墙体穿透等级。
- 开火声音半径。
- 消音/非消音标记。

### 6.3 命中模型

建议采用：

- Hitscan 为主。
- 少数特殊武器/道具使用 Projectile。
- 服务端权威判定命中。
- 客户端做本地开火表现和命中预测反馈。
- 服务端结果回传后纠正。

关键要求：

- 命中盒与动画姿态必须定期校验。
- 头部 Hitbox 不能过大。
- 第三人称模型姿态要和第一人称开火方向一致。
- 高 Ping 玩家不能明显获得离谱优势。

### 6.4 后坐力与扩散

建议使用“固定模式 + 小幅随机”的混合模型：

- 前 5 到 8 发形成可学习的固定上扬曲线。
- 长连发加入可控水平摆动。
- 移动、跳跃、落地带来显著扩散惩罚。
- 蹲下略微降低扩散，但不应成为万能姿态。

目标：

- 新手能理解“停下打更准”。
- 高手能学习压枪。
- 随机性不能盖过技术。

### 6.5 穿透系统

初版只做简化穿透：

- 材质定义穿透等级：无、轻、中、重。
- 武器定义穿透能力：无、轻、中、重。
- 命中墙体后根据材质厚度和武器能力衰减伤害。
- 不做复杂弹道反弹。

地图设计必须标记：

- 可穿点位。
- 不可穿核心掩体。
- 视觉上能看出材质差异。

## 7. 道具与职能装备

### 7.1 通用道具

建议初版通用道具：

1. 烟幕弹
   - 持续 14 秒。
   - 形成清晰球形/柱形遮蔽。
   - 声音提示落点与展开。

2. 闪光弹
   - 根据视角角度和距离决定致盲强度。
   - 背闪只造成轻微白屏/听觉压制。
   - 必须有明显投掷和爆闪声音。

3. 爆破雷
   - 低到中伤害，用于清近点。
   - 不能随便一颗满血秒杀重甲。

4. 诱饵器
   - 模拟脚步/换弹/开火声音。
   - 可被经验丰富玩家识别，但能制造残局心理压力。

### 7.2 职能装备示例

突入装备：

- 突破震撼弹：短时间降低受影响玩家转向和听觉清晰度。
- 定向闪：可贴墙反弹一次，适合进点。

控场装备：

- 定点烟幕发射器：可从战术地图选择近中距离落点。
- 干扰场：短时阻断侦察设备，不造成直接伤害。

侦察装备：

- 脉冲探针：发射后扫描一次范围内移动目标。
- 微型摄像器：可放置，可被看见和摧毁。

支援装备：

- 弹药补给包：补充少量备用弹药，不补满道具。
- 防爆垫片：短时降低爆炸伤害，不能挡子弹。

锚点装备：

- 感应绊线：触发后发声并短暂标记区域，不造成高伤害。
- 阻滞胶囊：制造短时减速区域，有明显地面提示。

### 7.3 道具平衡公式

每个道具必须用以下维度评估：

- 成本。
- 投放难度。
- 生效延迟。
- 持续时间。
- 影响范围。
- 信息强度。
- 伤害强度。
- 反制方式。
- 误伤风险。
- 队友配合收益。

一条铁律：

**越容易使用、越难反制、越安全的道具，收益必须越低。**

## 8. 爆破器系统

### 8.1 爆破器规则

爆破器是进攻方核心目标物。

基础规则：

- 回合开始时随机或队长指定一名进攻方携带。
- 携带者死亡后爆破器掉落。
- 队友可拾取。
- 爆破器在小地图和世界中对队友显示。
- 防守方只能在看见或听见相关行为后获得信息，不默认全图显示掉落位置。

### 8.2 安装

安装条件：

- 玩家在爆破点区域内。
- 玩家持有爆破器。
- 玩家按住安装键。
- 玩家未受到硬控。
- 玩家未移动、未切枪、未开火。

安装反馈：

- 第一人称安装动画。
- 第三人称安装动画。
- 安装进度条。
- 明显安装声音。
- 队友 HUD 提示。
- 防守方在合理距离内可听见。

### 8.3 拆除

拆除条件：

- 防守方玩家在爆破器交互范围内。
- 按住拆除键。
- 未移动、未切枪、未开火。

拆除反馈：

- 拆除音效随距离衰减。
- 拆除进度条仅拆除者和队友可见。
- 进度不保留或半保留需要单独平衡；初版建议不保留，减少复杂度。

### 8.4 爆破器 UI

HUD 必须包含：

- 爆破器携带状态。
- 掉落状态。
- 安装中状态。
- 已安装倒计时。
- 拆除中状态。
- 回合胜负原因。

声音必须包含：

- 拾取。
- 掉落。
- 开始安装。
- 安装完成。
- 倒计时阶段变化。
- 开始拆除。
- 拆除完成。
- 即将爆炸。
- 爆炸。

## 9. 地图设计

### 9.1 首张地图方向

建议首张地图代号：`BO_Map_Foundry`

主题：近未来港口维修厂 / 工业园区 / 物流仓储中心。  
选择理由：

- 可复用当前 LevelPrototyping 几何快速灰盒。
- 工业材质容易表达可穿/不可穿墙体。
- 视觉遮挡、管线、集装箱、维修平台适合战术 FPS。
- 美术成本比城市街区或科幻基地更可控。

### 9.2 地图结构

标准结构：

- A 点：空间较开阔，适合烟幕封线和远点架枪。
- B 点：空间较紧，适合近点清理和锚点防守。
- 中路：连接双方出生、A/B 转点、前压风险区域。
- 进攻出生：至少两条离开路线。
- 防守出生：回防 A/B 时间接近，但防守开局不能同时轻松控制所有关键区。

### 9.3 时间指标

灰盒阶段必须测量：

- 进攻方最快到首个交火点：8 到 12 秒。
- 防守方最快到首个交火点：6 到 10 秒。
- A 点到 B 点回防时间：12 到 18 秒。
- 中路控制后转 A/B 时间：6 到 10 秒。
- 安包后从常见防守回防点到爆破器：6 到 12 秒。

如果一张地图无法满足这些时间指标，就需要调整比例。

### 9.4 空间指标

UE 单位按厘米。

建议初版角色指标：

- 角色胶囊半径：34 cm 左右。
- 角色胶囊半高：88 cm 左右。
- 站立头部高度：约 160 到 175 cm。
- 标准门宽：120 到 160 cm。
- 双人并行通道宽度：220 到 280 cm。
- 单人紧张通道宽度：100 到 140 cm。
- 掩体高度：
  - 半身掩体：90 到 110 cm。
  - 头线掩体：140 到 160 cm。
  - 全遮挡：180 cm 以上。

### 9.5 竞技地图检查表

每张地图必须检查：

- 是否有两个明确爆破点。
- 是否有中路或等价控图资源。
- 是否存在不可反制的一枪位。
- 是否存在过强防守交叉火力。
- 是否存在进攻方永远不值得走的路线。
- 是否存在低风险假打转点路线。
- 是否有太多垂直角度导致新手完全不可读。
- 是否有声音遮挡和脚步距离可读性。
- 是否有过多杂物影响命中判定。
- 是否有视觉噪音影响敌人识别。
- 是否有可穿材质和不可穿材质的视觉差异。
- 是否有清晰 callout 区域名。

### 9.6 地图制作流程

1. 纸面布局
   - 只画路线、爆点、出生、关键 choke、回防线。

2. UE 灰盒
   - 使用 `LevelPrototyping` 几何体。
   - 不做美术细节。
   - 只验证时间、角度、交火距离。

3. Bot 跑图和人肉测试
   - 测出生到点位时间。
   - 测进攻/防守首波接触。
   - 测 1vX 残局可玩性。

4. 竞技迭代
   - 每次只改少量区域。
   - 记录改动原因。
   - 用数据看双方胜率和点位使用率。

5. 美术白盒
   - 确定主题、材质、光照方向。
   - 保持敌人轮廓清晰。

6. 最终美术
   - 逐区替换资产。
   - 不破坏碰撞和头线。
   - 性能预算必须通过。

## 10. 角色、动画与表现

### 10.1 第一人称与第三人称分离

竞技 FPS 建议分离：

- 第一人称手臂和武器：服务于手感、视野和反馈。
- 第三人称全身角色：服务于对手识别、命中盒和观战。

不能直接让第一人称动画决定真实命中方向。真实开火方向应由摄像机、武器规则和服务端验证共同决定。

- 站立待机。
- 行走/奔跑。
- 蹲下。
- 跳跃/落地。
- 换弹。
- 掏枪/收枪。
- 开火。
- 受击。
- 死亡。
- 安装爆破器。
- 拆除爆破器。
- 投掷道具。

第三人称必须让敌人看懂：

- 正在投掷。

## 13. Unreal 技术架构

### 13.1 总体建议

当前项目是蓝图模板。建议路线：

1. 保留蓝图模板作为参考和快速原型。
2. 新建 C++ Gameplay Framework 基类。
3. 核心联网逻辑用 C++。
4. 可视表现、UI、动画状态、道具变体用蓝图和数据资产。
5. 所有武器、道具、地图规则数据化。

### 13.2 推荐模块

建议新增 C++ 模块：

- `BlastOperation`
  - 主游戏模块。
- `BOCore`
  - 通用类型、Gameplay Tags、日志、配置、数据资产基类。
- `BOGameplay`
  - 角色、武器、伤害、回合、爆破器、队伍、经济。
- `BOOnline`
  - 登录、会话、匹配、掉线重连、反作弊接口。
- `BOUI`
  - HUD、菜单、设置、买装、计分板。
- `BOAI`
  - 训练 Bot、StateTree、EQS、靶场逻辑。

早期可以先放在一个游戏模块里，但代码目录应按这些边界组织，方便后续拆分。

### 13.3 Gameplay Framework 映射

核心类建议：

- `ABOGameMode`
  - 只存在于服务器。
  - 控制匹配规则、回合状态、出生、胜负、经济结算。

- `ABOGameState`
  - 服务器和所有客户端都有。
  - 复制比分、回合阶段、计时器、爆破器状态、队伍状态。

- `ABOPlayerController`
  - 输入、HUD、买装请求、观战切换、客户端 RPC。

- `ABOPlayerState`
  - 玩家名、队伍、击杀/死亡/助攻、经济、装备摘要、延迟、排位分。

- `ABOCharacter`
  - 移动、生命、受击、武器挂点、交互。

- `ABOWeapon`
  - 武器表现和持有状态。

- `UBOWeaponComponent`
  - 开火、换弹、弹药、后坐力、命中请求。

- `ABOBomb`
  - 爆破器携带、掉落、安装、拆除、爆炸。

- `UBOInventoryComponent`
  - 武器和道具持有。

- `UBODamageComponent`
  - 生命、护甲、伤害应用。

- `UBOTeamComponent`
  - 队伍标识、友伤规则、队友识别。

- `UBORoundComponent` 或 `ABORoundManager`
  - 回合状态机。

## 14. 联网架构

### 14.1 基本原则

本项目必须采用：

- 服务器权威。
- 客户端预测。
- 服务端校验。
- 必要时服务端回滚/延迟补偿。
- 客户端表现与真实状态分层。

### 14.2 服务器权威内容

服务器决定：

- 玩家出生。
- 回合阶段。
- 金钱变化。
- 购买是否成功。
- 武器弹药真实数量。
- 命中结果。
- 伤害。
- 死亡。
- 爆破器安装/拆除/爆炸。
- 道具真实生效。
- 胜负。

客户端可以预测：

- 开火表现。
- 后坐力镜头。
- 换弹动画。
- 道具投掷动画。
- UI 临时反馈。

### 14.3 命中延迟补偿

竞技 FPS 必须处理延迟。

建议方案：

- 服务器记录最近若干毫秒内玩家 Hitbox 历史。
- 客户端开火时发送时间戳、视角、武器状态、随机种子索引。
- 服务器根据玩家延迟回溯目标位置。
- 服务器做射线检测并裁定结果。
- 限制最大回溯窗口，防止高 Ping 过度优势。

初版可先实现简单服务器即时命中；一旦做线上测试，必须加入延迟补偿。

### 14.4 复制策略

复制内容优先级：

高优先级：

- 玩家位置和姿态。
- 开火事件。
- 受击/死亡。
- 爆破器状态。
- 回合计时。
- 道具生效区。

中优先级：

- 装备摘要。
- 经济。
- 计分板。
- 观战状态。

低优先级：

- 外观皮肤。
- 非关键环境交互。
- 装饰性效果。

### 14.5 Iris 与传统复制

UE 5.8 支持传统复制系统、Replication Graph 与 Iris。建议：

- MVP 阶段使用传统复制系统。
- 5v5 小规模竞技不急于启用 Iris。
- 先用 Network Insights 找出真实瓶颈。
- 当项目出现大量复制 Actor、复杂道具场、观战/回放压力时，再评估 Iris 或 Replication Graph。

原因：

- Iris 仍需要谨慎评估和迁移测试。
- 过早引入会增加调试复杂度。
- 对 10 名玩家的垂直切片收益有限。

### 14.6 专用服务器

竞技模式最终必须使用 Dedicated Server。

开发阶段路线：

1. 单机 PIE 验证。
2. Listen Server 双客户端验证。
3. 本机 Dedicated Server 验证。
4. 局域网多机验证。
5. 云服务器小规模测试。
6. 区域服务器和匹配系统。

### 14.7 掉线重连

标准爆破需要支持：

- 玩家短线后保留 PlayerState。
- 回合中重连进入观战或回到角色，视规则决定。
- 买装阶段重连恢复经济和装备。
- 比赛结束前不释放关键统计。

## 15. 反作弊与安全

### 15.1 设计原则

反作弊不是最后加的插件，而是架构原则：

- 客户端永远不可信。
- 客户端不告诉服务器“我打中了谁”，只告诉服务器“我何时以什么角度开火”。
- 经济、伤害、胜负全部服务器计算。
- 关键数据留日志和回放。

### 15.2 初版防线

MVP 阶段：

- 服务端验证购买价格和经济。
- 服务端验证弹药。
- 服务端验证射速。
- 服务端验证换弹时间。
- 服务端验证移动速度。
- 服务端验证安装/拆除距离。
- 服务端验证道具数量。
- 服务端记录异常命中率、爆头率、穿墙击杀、视角变化。

### 15.3 中后期防线

线上测试前：

- 集成 Easy Anti-Cheat 或 EOS Anti-Cheat。
- 服务端回放。
- 玩家举报。
- 自动异常检测。
- 封禁和申诉流程。
- 排位高分段加强审查。

### 15.4 常见作弊防护点

需要防：

- 自瞄。
- 透视。
- 无后坐。
- 射速修改。
- 弹药修改。
- 移速修改。
- 瞬移。
- 经济修改。
- 道具数量修改。
- 假 Ping / 延迟滥用。

## 16. AI 与训练

### 16.1 当前基础

项目已有：

- `BP_ShooterNPC`
- `BP_ShooterAIController`
- `ST_Shooter`
- `EQS_FindSnipingLocation`
- `EQS_FindRoamLocation`

这些可以作为训练 Bot 原型，但不应作为竞技线上 Bot 的最终实现。

### 16.2 训练场

训练场是早期高价值内容。

功能：

- 固定靶。
- 移动靶。
- 爆头练习。
- 压枪墙。
- 投掷物落点练习。
- 武器换弹/射速测试。
- 道具效果预览。
- 爆破器安装/拆除练习。

### 16.3 Bot 目标

初期 Bot 只需服务测试：

- 能移动到目标点。
- 能发现敌人。
- 能开火。
- 能安装/拆除。
- 能使用少量道具。
- 能模拟站点防守。

不要早期追求高智能 Bot。真正的竞技体验必须靠真人测试。

## 17. 美术方向

### 17.1 世界观基调

建议方向：近未来现实战术。

关键词：

- 工业城市。
- 港口物流。
- 私营安全承包商。
- 高价值设施争夺。
- 可识别战术装备。
- 少量未来科技。

不建议：

- 过度科幻。
- 魔法英雄。
- 过度写实血腥。
- 昏暗到看不清敌人。
- 皮肤特效影响竞技读图。

### 17.2 阵营视觉

两方阵营要有轮廓差异：

- 进攻方：轻装、机动、破拆装备。
- 防守方：重装、设施防卫、区域控制装备。

但注意：

- 不应因皮肤导致一方更难看见。
- 所有皮肤必须通过地图背景可见性测试。
- 敌我识别不能完全依赖 UI 描边。

### 17.3 武器视觉

武器应满足：

- 第一人称占屏合理。
- 不遮挡右侧/下方过多信息。
- 换弹动作清楚。
- 皮肤不改变枪械轮廓太多。
- 枪口火焰不遮挡连续压枪视野。

### 17.4 地图视觉

竞技地图视觉优先级：

1. 敌人可见。
2. 路线可读。
3. 掩体可读。
4. 道具效果可读。
5. 美术氛围。

不要为了美术细节牺牲竞技清晰度。

## 18. 商业化与长期运营

### 18.1 商业化原则

只能卖外观，不能卖强度。

可售内容：

- 武器皮肤。
- 手套。
- 近战皮肤。
- 挂饰。
- 喷漆。
- 名片。
- 击杀横幅。
- 通行证。

不应售卖：

- 更强武器。
- 更强角色。
- 付费属性。
- 影响命中盒的外观。
- 影响声音识别的皮肤。

### 18.2 赛季结构

建议每赛季 8 到 12 周。

赛季内容：

- 小型平衡补丁。
- 新皮肤。
- 通行证。
- 地图微调。
- 排位重置。
- 限时活动。

大版本：

- 新地图。
- 新武器。
- 新职能装备。
- 新训练功能。

### 18.3 排位系统

排位目标：

- 尽量匹配实力接近玩家。
- 惩罚挂机和恶意退出。
- 奖励团队胜利，不鼓励刷数据。

段位可先设计：

- 青铜。
- 白银。
- 黄金。
- 铂金。
- 钻石。
- 精英。
- 战术大师。

内部使用 MMR，外部显示段位。

### 18.4 赛事观战

后期需要：

- 自由视角。
- 队伍装备总览。
- 经济趋势。
- 小地图战术视图。
- 回合事件时间线。
- 回放导出。

## 24. 风险清单

### 24.1 技术风险

风险：蓝图堆叠导致联网调试困难。  
应对：核心规则尽快 C++ 化。

风险：命中判定不可信。  
应对：服务器权威、延迟补偿、回放。

风险：专用服务器太晚接入。  
应对：阶段 3 前必须完成 Dedicated Server 流程。

风险：美术过早精修地图。  
应对：灰盒胜率和路线验证前不做最终美术。

### 24.2 设计风险

风险：道具过强导致枪法失去价值。  
应对：道具创造窗口，不直接替代击杀。

风险：地图防守方过强。  
应对：中路、转点、烟闪配合和点内掩体一起调。

风险：经济雪球过大。  
应对：连败补偿、低价武器有效性、手枪局影响控制。

风险：角色/职能组合不可控。  
应对：先做少量职能装备，逐个验证。

### 24.3 运营风险

风险：作弊影响口碑。  
应对：服务器权威、反作弊、举报、回放、封禁流程。

风险：匹配等待过长。  
应对：早期控制模式数量和地区分区。

风险：新手被劝退。  
应对：训练场、新手匹配、清晰教程、死亡回放提示。

## 27. 当前建议结论

《爆破行动》的最佳起步方向不是先做大量角色和皮肤，而是先建立一条强硬的竞技主线：

**UE5.8 C++/蓝图混合架构 + 服务器权威 5v5 爆破 + 数据驱动枪械 + 轻量职能装备 + 第一张灰盒竞技地图 + 每周真人测试。**

只要第一张灰盒图、两把枪、一个爆破器、一个回合状态机能让人愿意反复打，后面的内容扩张才有意义。反过来，如果基础枪感、联网裁定和地图回合节奏不成立，再多技能、皮肤和故事都救不了项目。
